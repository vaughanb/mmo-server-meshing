Lets a client reconnect to another server without the client teardown, keeping the objects it has on screen so the new server's spawns adopt them instead of destroying and re-creating them. Nothing changes for a game that does not call `MigrateClient`.

**Moving the client.** `LiteNetLibManager.MigrateClient(address, port)` reconnects the transport while `IsClient` and the logic updater keep running. An overload takes an `ITransport` already connected to the new server (opened ahead of time), so no connect round trip is spent. `EndMigrateClient` ends it, and `IsMigratingClient` is true in between. `LiteNetLibClient` gains `AdoptConnectedTransport` for the second form.

**Keeping the objects.** `LiteNetLibGameManager` keeps the client's spawned objects (`LiteNetLibAssets.KeepSpawnedObjects`) instead of destroying them. It holds the old connection id until the new server answers, so owned objects stay owned and simulated, then rebinds their owner to the new id.

**Adopting them.** On a migrating client, `NetworkSpawn` adopts the kept object a spawn is, by `ResolveKeptObject`: same prefab and ownership, the owned one or the nearest within `keptObjectAdoptDistance`, or a `keptObjectResolver`. It raises `onObjectAdopted` with the previous id. `DestroyKeptObjects` removes what no spawn adopted, and `Assets.Clear` calls it, so a scene load during a migration still leaves nothing behind. `WarmUpAdoption` runs the adoption read once ahead of time, so it is not compiled in the frame of the first adoption.

**Initial state as a diff.** An adopted object was live a moment ago, so its initial state is applied as a change. A sync field fires its callbacks only for a value that differs, and a sync list is brought to the state it was sent with Set/Add/RemoveLast operations (entries compared in wire form) instead of Clear plus AddInitial. Listeners such as appearance, stat caches and UI only hear about what changed.

**One log change.** On a client, an owner change for an object not spawned yet logs at dev level instead of warning: the owner message overtakes the spawn, and the spawn carries the owner.

Tests: `KeptObjectAdoptionTests` and `PreconnectedMigrationTests` (EditMode).

This is the client half of a server-meshing add-on whose players walk between map-server processes of one map with nothing on screen torn down at the crossing. It has been running there on the kit at f43d0c0 with the add-on's regression harness. It applies cleanly to `develop` at dc025c2, but has not been compiled at that commit outside CI, so these checks are its first build there.
