## Summary
Step 5 can be tested almost entirely in EditMode, but the testable logic has to live in pure types. I read the code but compiled nothing. Repo root: C:\dev\Game Design\mmo-server-meshing.

What a test can do:
(1) A test class can implement all 18 ITransport members. ITransport.cs:8-25 has 6 properties and 12 methods. Every type they use is public: TransportEventData has public fields, NetDataReader is the reader type (not NetPacketReader), DisconnectInfo has a public Reason, and DeliveryMethod is a public enum. The LiteNetLib and LiteNetLibManager asmdefs are autoReferenced, so MeshFakeTransport (an internal sealed fake, like MeshFakeKitHandler) is straightforward. It can also implement IMeshWrappedTransport, so it can stand in as a generic wrapper in the Innermost tests.
(2) `new LiteNetLibTransport(key, 16, 16)` only allocates collections. No NetManager or socket exists until StartServer or StartClient, so it is safe as long as tests never call those (the rig holds the ports). NetDataWriter and NetDataReader are public and pure. NetDataReader's public `(byte[], offset, maxSize)` constructor can stand in for a NetPacketReader's header offset. NetPacketReader itself is sealed with an internal constructor and cannot be built, but it is not needed. TooBigPacketException has a public string constructor.
(3) A LiteNetLibIdentity can be added with AddComponent in EditMode; step 3 already does this. IsHideFrom (LNI:815-859) runs without a server. Its ConnectionId setter is internal (LNI:188), so the hidden-from-a-non-owner case needs reflection: PropertyInfo.SetValue uses the non-public setter. Reflection on kit members already has precedents in MeshKitEditTests.cs:11 and ServerMeshAoiCountdownTests.cs:90. ForceHideFunctions is a global static list, so TearDown must remove the delegate.
(4) An upload can be parsed with EntityMovementFunctions.ServerReadSyncTransformMessage3D (EntityMovementFunctions.cs:157-163). That is exactly what BIEMF3D:1554 calls, and it touches neither the grid nor a scene. The client reader (165-184) does touch DefaultGridManagerComponent.Instance. BIEMF3D.ReadClientStateAtServer itself cannot be called: it goes through Entity and IsOwnerClient. The input payload reader ReadMovementInputMessage3D (90-103) is also pure.
(5) The step 3 golden tests are in MeshKinematicCharacterBodyTests.cs. They have a private Hex helper (BitConverter over CopyData), TestCaseSource GoldenCases with SetName, a round trip through the kit reader that asserts EndOfData, and FormatterServices.GetUninitializedObject for the kit handler types.

Two blockers for test design:
(a) The kit's `Logging.*` very likely throws NullReferenceException in EditMode. LogManager.LoggerManager is only set by a RuntimeInitializeOnLoadMethod(BeforeSceneLoad) (LogManager.cs:61-66), and Logging.cs:16 dereferences it without a null check. That matches the existing pattern: pure helpers return `out string error/warning`, or take IMeshLog (MeshLayoutCoordinator.cs:30-43) with MeshFakeLog in tests. The phantom transport, meter, layout, uploads and settings must follow it.
(b) EditMode never runs Awake, so the factories and the eye must not set themselves up in Awake.
