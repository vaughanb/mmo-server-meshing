# sinkrig

## Summary
Read-only survey of the sink (real LiteNetLib peers from machine B) and the rig plumbing that step 5 plugs into. Nothing was modified or run. Main findings:

(1) Manual mode works the way the plan needs, with three catches.
- `StartInManualMode` binds and starts no threads. `PollEvents` then reads the sockets and fires the listener callbacks inline, and `ManualUpdate` flushes sends, acks and pings. The doc comment saying "use ManualReceive (without PollEvents)" is stale: `ManualReceive` is private.
- Catch 1: under Unity, every NetManager's `Start` subscribes a PausedSocketFix to `Application.focusChanged` and `Application.quitting`. On quit it calls `Stop()` from the main thread, which races the sink's worker threads. `NetManager` cannot turn the fix off.
- Catch 2: `NetManager.ChannelsCount` defaults to 1. The kit's server uses 16. With the default, the sink silently drops server packets on channels 1 and up, and silently never sends uploads on channel 2.
- Catch 3: `EnableStatistics` defaults to false everywhere.

(2) Connect key and message ids.
- The key is "SampleConnectKey": no prefab or asset sets a LiteNetLibTransportFactory, so the kit adds one with that default, plus 16/16 channels and maxConnections 1100.
- Ids 65000 and 65001 collide with nothing on the game transport. The kit's highest ids are GameMsgTypes 10, game messages 122 and request subtypes 194 (those sit inside the 0/1 envelopes). Unknown ids are silently ignored.
- The hello encodes as bytes [249,244,248] and the bind reply as [249,244,249].

(3) BytesSent comparison.
- Server-side `BytesSent` counts raw datagrams sent to all peers, headers, acks and pings included. "Sink bytes within ±3%" is only meaningful against the sink managers' `BytesReceived` (raw), in a run with no other peers.
- The server already sets `EnableStatistics` (MeshMapNetworkManager.cs:648-649).

(4) Rig plumbing.
- ENV_KEYS is at Tools/ServerMeshing/regress.py:69-81; the sheet's Tools/regress.py:59-64 is stale.
- All 8 step-5 keys are still in p0tools.PENDING_KEYS. They must move to ENV_REGISTRY and ENV_KEYS within step 5, because `regress --env`, `rigrun.check_env` and test_p0tools all refuse them otherwise. The sheet defers "the ENV_KEYS additions" to step 8, which conflicts.
- Env reaches the zone servers through ServerMeshPlayRunner's env.KEY lines, then the editor process, then the spawner's child processes. Bots never see it: `launch_bot` inherits Python's environment. The editor sees it too, so the phantom installer and the metered factory would also run on the editor's client-side manager.
- p0plans refuses fanout/packets/crossings/calibrate (`STAGE_LATER`) and presence `--observed`.
- remoteb.py has no sink command. Its `running`/`stop` treat any kit-ce-project process as a cell, and `fetch` copies only `{dir}/Logs/*.log`.
- A sink process gets no kit file log (that logger is only enabled for server roles), so it needs `-logFile` under Logs.

(5) Sheet line references that are stale:
- The `is LiteNetLibTransport` site is Ghosting.cs:168, not :164.
- _Load.cs:210 is the registeredPlayers loop. The client count is at _Load.cs:259-263 and Ghosting.cs:167-171, and window lines are logged at _Load.cs:152-156.
- The reserved-name list in §0.4 is stale: the stray check derives about 95 names. Driver is at MeshMeasurementTests.cs:171, not :56, and the check itself is at ServerMeshPackageBuilder.cs:226-248.
- The packed-int cite 169-186 misses the 3-byte form, which is at :191-197.
- The TooBig rule is incomplete: Sequenced and ReliableSequenced also throw, at MTU−4. MTU is 1164.

(6) TestMap prefabs.
- They were hand-made in the editor; there is no builder script and no Resources folder.
- LiteNetLibIdentity.assetId is assigned from the prefab guid by an editor-only OnValidate.
- They reach the build through GameDatabase-CE.asset or scene references. The eye prefab needs a path into the player build as well as the §0.1 build window, which is a time slot when no rig chain runs.

## risks
- The sink's NetManager must set ChannelsCount = 16; it defaults to 1 (NetManager.cs:16). Otherwise server packets on channels 1 and up are silently dropped (NetPeer.cs:227-230) and uploads on channel 2 are silently not sent (LiteNetPeer.cs:611). The result would be zero binds and a byte mismatch, with no error anywhere.
- PausedSocketFix: every NetManager.Start under UNITY_SOCKET_FIX subscribes Application.focusChanged and Application.quitting from the calling thread (PausedSocketFix.cs:16-26). On quit it calls Stop() from the main thread while sink worker threads are still polling, and LiteNetLib in manual mode is not thread-safe. NetManager cannot turn the fix off (NetManager.cs:62). The sink should stop its own managers and join its threads before the application quits.
- EnableStatistics defaults to false (LiteNetManager.cs:201). Sink managers must enable it for BytesReceived. The bot's client NetManager is recreated on every StartClient and every migration (LiteNetLibTransport.cs:57), so the Bot net window must re-enable statistics and handle counters resetting.
- Env does not reach bots: launch_bot uses Popen with no env (regress.py:196-202). A Bot net window gated by an env key would never fire on bots.
- The editor process gets every env key (ServerMeshPlayRunner.cs:266-271). The phantom installer and the MESH_METER_SENDS factory would then also run on the editor's client-side MeshMapNetworkManager. The installer should gate on a map-server process (-startMapServer; MMOServerInstance.cs:731).
- The ±3% sink acceptance needs like-for-like counters. Server Statistics.BytesSent counts raw datagrams to every peer, with headers, acks and pings (Socket.cs:646-650). Comparing it with the sink's payload bytes would miss by more than 3% for small packets. The run must also have no other peers (request_play enabled=False, no bots), or use per-peer statistics.
- remoteb.running() counts any kit-ce-project process (remoteb.py:77-79), so `start` refuses while a sink runs, and `stop` kills the sink (remoteb.py:197-207). A remote cell and a sink on B conflict.
- A sink process gets no kit file logger (MMOServerInstance.cs:692-748). Its lines go to Unity's log and are lost to `remoteb fetch` unless it is started with -logFile <dir>\Logs\<name>.log.
- Cell ports are assigned by the spawner in spawn order and the cell does not log its own port. The sink must learn the target port from a neighbour's 'Zone peer registered' line (MeshMapNetworkManager.cs:715).
- Connect attempts give up after 10 × 500 ms (LiteNetManager.cs:174-179), so the sink must start after the cell is serving, or retry. A sink thread that stalls for more than 5 s (DisconnectTimeout) gets disconnected by the server.
- In manual mode, unreliable sends and acks only leave at ManualUpdate. Windows Sleep granularity (up to about 15.6 ms) quantizes 20 Hz uploads; pace the loop deliberately.
- A server Teleport on a client-owned phantom or sink character makes the server ignore every upload until one carries IsTeleport (BIEMF3D:376-377, 1555-1564). Without handling, the character stalls silently.
- The ownership check at BGNM:583 means sink characters must be spawned with the sink peer's real LiteNetLib connection id. LiteNetLib recycles peer ids (LiteNetManager.cs:681-682), so the hello-to-index map must be cleared on disconnect.
- regress grade_common fails any zone line containing 'Exception' (regress.py:572-577), and the kit's Logging runs AppendFormat (DefaultLogger), so braces break it. New phantom and transport log lines must never print TooBigPacketException type names or braces.
- The stray check is whole-word, case-sensitive and includes comments. Mesh/ text must not contain a capitalised 'Mode', 'Driver', 'Callbacks' or 'Placement', or any phantom TestMap name or MeshFakeTransport, including at the start of a comment sentence.
- The sheet puts MeshMeteredTransportFactory (a MonoBehaviour, via BaseTransportFactory) inside MeshMeteredTransport.cs. A Unity MonoBehaviour whose file name differs from its class name is fragile; give each factory its own file.
- The eye prefab cannot reach the player build without a reference or a Resources folder; none exists in ServerMeshing today. Its LiteNetLibIdentity assetId is assigned only in the editor.
- Switching the client count to ServerTransport.ServerPeersCount makes the stats line, the Work window line and the load report include phantoms. That is fine for logs, but the results schema wants real, phantom_virtual and phantom_sink separately (p0results.py:148), so real peers must also be reported on their own.
