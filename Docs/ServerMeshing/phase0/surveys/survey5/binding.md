# binding

## Summary
I read the step 5 sheet (625-716), its rules (94-272) and step 6 (717-816) against today's code. Everything below comes from reading files only: I changed nothing and started no process.

**A phantom can be bound safely without EnterGame, ClientReady, the database or the central.** The safe sequence, in order:

1. **Connect.** The phantom transport returns a ConnectEvent for id 1,000,000+k from ServerReceive. LiteNetLibServer.OnServerReceive (LiteNetLibServer.cs:94-98) then adds the id to Server.ConnectionIds and calls Manager.OnPeerConnected. That passes through MeshMapNetworkManager:312 and BGNM:337-350 (the only kick there is IsTemporarilyClose) to LNGM:437-442, which adds the LiteNetLibPlayer.
2. **Wait** until `mesh.TryGetPlayer(id)` succeeds (LNGM:142-145). Spawning with an owner that is not yet in Players throws a null reference: Initial calls `Player.SpawnedObjects.Add` and `Player.Subscribe` (LNI:597-601).
3. **Set `player.IsReady = true`** (public setter, LNP:11) before any spawn. IsReady is the only thing that gates:
   - the spawn-time subscription in NotifyNewObject (BaseInterestManager.cs:30-37);
   - the AOI (JGAOI:187 and 305);
   - the sync pass (StateSyncing.cs:381 and 398).
   The kit's EntityState sender has no gate at all: it loops over every entry in Players (BGNM:674). The grid/job path is the exception: it skips any connection with no registered character (BGNM:792-793). The grid is off by default (DefaultGridManagerComponent.cs:22).
4. **Character kind.** Copy the load generator's data preparation (ServerMeshLoadGenerator.cs:166-187):
   - give each phantom a unique id that includes the cell;
   - for the input row, set both `ccem.movementSecure` and `ccem.Functions.movementSecure` (both public) after GetObjectInstance and before spawning;
   - spawn with `Assets.NetworkSpawn(identity, 0, id)` (LiteNetLibAssets.cs:456-480);
   - then ForceMakeCaches, FillEmptySlots and HP, then `mesh.TrackSyntheticEntity(entity)`. It is `internal`, which is reachable because TestMap and Mesh both compile into Assembly-CSharp. It sits at Ghosting:109-110 now, not :106;
   - leave DoNotDestroyWhenDisconnect false, add no PlayerCharacterDataUpdater, and do not call RegisterPlayerCharacter.
5. **Eye kind.** Hide the eye *before* NetworkSpawn: NotifyNewObject subscribes the other ready players inside the spawn call itself (LNI:603, BaseInterestManager.cs:38-53). Then spawn it owned by the id. The owner always sees its own eye because the owner check runs first (LNI:822-826 and BaseInterestManager.cs:65-66).
6. **Uploads.** Build the 119 frame exactly as BGNM:632-635 does and inject it as a DataEvent. HandleClientEntityStateAtServer accepts it only when `handler.ConnectionId == id` (BGNM:584).
7. **Unbind.** On QueueDisconnect, the disconnect chain destroys the phantom's objects (LNP:83-96). It ends in the kit's SaveAndDespawnPlayerCharacter, which takes its "not registered" branch (PlayerDespawning.cs:97-101), so nothing is saved.

**What a phantom skips, all confirmed:**
- the DB token check, character load, relates data (party, guild, storage), summons, mount and respawn RPCs (MapNetworkManager.cs:450-539, 581-618, 622-763, 765-847);
- registration (social mirror and the UpdateMapUser messages to the central, 276-285);
- the DB save hookup (PlayerCharacterDataUpdater at 761-762);
- online updates (230-239);
- the handoff boundary tick, which only walks registered characters (MeshMapNetworkManager.cs:843).

**What breaks or changes:**
- **Registering phantoms** (MESH_PHANTOM_REGISTER, which the step body never describes):
  - it sends central traffic every second and inflates the central's `currentUsers` (MapNetworkManager.cs:183);
  - it makes phantoms eligible for handoff, and a handoff does a DB save plus a Warp (MeshMapNetworkManager.cs:936-981);
  - AddPlayerCharacter refuses an empty UserId, and a null one throws in the social map.
- **Monsters kill brainless phantom characters.** The F2 row is "all fighting". A dead character's uploads are rejected (BIEMF3D:1601-1609).
- **Any server Teleport freezes a phantom-owned character's uploads** until an upload carries IsTeleport (BIEMF3D:376-377, 1555-1564, 483-486).
- **Stats:** Mesh stats `players=` excludes phantoms; `owned=` includes phantom characters; `clients=` counts only real LiteNetLib peers, sink included, virtual phantoms not.
- **Sleep:** a cell refuses to sleep while Players.Count > 0 (MeshMapNetworkManager.cs:1047), but the central counts registered users only.

**Sheet errors that matter** (details in contradictions):
- The `is LiteNetLibTransport` sites are now at Ghosting:168 and Load:259/262, not :164 and :210.
- "MapNetworkManager.cs:553-714" leaves out EnterGame and the end of SetPlayerReadyRoutine.
- Copying the kit's factory fallback "exactly" would make the wrapper factory return itself.
- ServerMeshPhantomTransport must implement IMeshWrappedTransport.
- MESH_PHANTOM has no cell selector.
- A ForceHide delegate puts a cost on every AOI pair. `SetIsHide` on the eye alone costs nothing elsewhere.
- `movementSecure` (E) is settled: it is settable per instance.

- sends UpdateMapUser Add and then Online every 1 s per phantom to the central (283, 237);

Dead characters reject feeder positions (BIEMF3D:1601-1609), which breaks the 'within 0.5 m at p95' acceptance and the V_move rows. Heal them (SyntheticPlayerBrain.HealWhenLow, ServerMeshLoadGenerator.cs:415-419) or run with MESH_NO_MONSTERS=1 when monsters are not the subject.
- Any server Teleport of a phantom-owned character (a kit respawn or fall path, step 6's CE-12 check) sets _isServerWaitingTeleportConfirm (BIEMF3D:376-377). The feeder's uploads are then ignored (1480-1483, 1560-1564) and interpolation stops (483-486) until an upload carries MovementState.IsTeleport. The virtual feeder needs a detect-and-confirm path. The kit strips the flag from server records (1371), so a one-shot echo is safe. The sink cannot see server positions and would freeze.

The bot gets a spawn for an unregistered asset hash, which fails 'a real bot in an eye group spawns no eye'.

- The metered or phantom factory inner, if resolved like the kit (GetComponent<BaseTransportFactory>(), LiteNetLibManager.cs:127), finds the wrapper itself, so Build recurses into a stack overflow. With useWebSocket the kit silently replaces a non-websocket factory (LiteNetLibManager.cs:113-123), dropping the meter. The rig runs with useWebSocket false.

- LiteNetLib statistics are never enabled (MeshMapNetworkManager.cs:648-649);
- Mesh stats clients and clientOut and the Work window clients go to 0;
