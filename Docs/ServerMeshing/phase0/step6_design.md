## Rules (the step 2/3/5 rules all bind; see `step2_design.md`, `step3_design.md`, `step5_design.md` "Rules")
- C# 9 on the overlap of netstandard 2.1 and unity-4.8-api (no records, no `init`, no default interface members; `readonly struct` and `in` allowed).
- XML docs on every public type and member, starting with its name; other comments minimal. Errors carry context (object id, type, connection); nothing is swallowed.
- No allocation per send, per build or per tick after warm-up. Growth of pooled tables (a new connection, a new pair, a new source) is warm-up; a test pins Build at zero bytes for a steady population.
- Log lines: one physical line, invariant culture, fixed numeric formats, no braces, never the word "Exception" (exception messages pass through `MeshStateSender.CleanForLog`, which turns `{`/`}` into `(`/`)` and "Exception" into "error"; type names of exceptions are never logged). ASCII units.
- Line prefixes: `State sender:` (setting, warnings), `State sender error:` (every error line of the sender, fan-out, wrap queue or adapter), `Sender window` (the stats line), `CE-12 check:` (TestMap). accept_step6.py fails on `State sender error:`.
- Names: Mesh/ never names a TestMap or Tests type, even in comments (not `MeshFakeServerStateHandler`, `MeshTickScheduleCopy`, `ServerMeshCe12Check`, `ServerMeshPhantom*`, `IServerMeshPhantomTruth`), never says "ship", never has a member named `Mode`, and writes "mode" in lower case. No nested helper types with generic names (Entry, Kind, State, Window). TestMap never names a Tests type.
- Default off and byte-identical: with `MESH_SENDER` and `MESH_CE12_CHECK` unset no component is added, no line appears, the OnServerUpdate override and LoadTick run today's code (two null checks added), the kinematic body behaves exactly as today, and the Send and Phantom window lines are byte-identical to step 5's (decision 25).
- Pure parts (packet writer, fan-out, wrap queue, adapter, policy, stats, CE-12 classifier, view sampler) take `IMeshLog` (`Mesh/MeshLayoutCoordinator.cs:30-35`; `MeshFakeLog` in Tests) or return error strings; only MeshStateSender and the TestMap MonoBehaviours use the kit's Logging (`MeshKitLog`), which NREs in EditMode (step 5 rule).
- Assemblies: Mesh/, TestMap/ and the kit's Core compile into Assembly-CSharp, but LiteNetLibManager is its own assembly (`ThirdParty/LiteNetLibManager/Scripts/LiteNetLibManager.asmdef`; InternalsVisibleTo only its own tests). Its `internal` members (`LiteNetLibAssets.SpawnedObjects`, the setter of `LiteNetLibIdentity.ConnectionId`, `LiteNetLibGameManager.Players` outside a subclass) are out of reach of Mesh/ and Tests: use the public members this contract names (`Assets.TryGetSpawnedObject`, `GetSpawnedObjects`, `TryGetPlayer`); tests set an owner by reflection on the `ConnectionId` property as `ServerMeshPhantomEyeHideTests.cs:13` does.
- Unity null: `== null` on UnityEngine.Object, never `??`, `?.` or `is null`; an interface-typed handler that may be a MonoBehaviour (NavMeshEntityMovement) is tested with `h is UnityEngine.Object o ? o == null : h == null`.
- Process: no `.meta` files by hand; no Unity, regress.py, rig or git writes by implementation agents; compile-check with `CSCHECK_OUT=<unique dir> python "...\2cf88996-...\scratchpad\cscheck.py" --editor` only while no rig chain runs; keep each file's line endings; one MonoBehaviour per file, named after the class; a MonoBehaviour declared in Tests/ (Assembly-CSharp-Editor) can never be AddComponent'ed (step 5 lesson), so fakes are plain classes and tests AddComponent only kit or Mesh/ types; never start a real socket in a test.

## Decisions (made; report them)
1. **CE-12 is the kit's pass shape and Mesh/ references it directly.** `IEntityMovementServerStateFlags` + `EntityMovementServerStateFlagsPass` (IEMDH:20-66), merged upstream as patch 0006 (`Docs/ServerMeshing/upstream/README.md`, "0006-0007: merged"). The add-on now requires a kit carrying 0006 (SETUP.md and upstream/README.md say so). Reason: it is upstream, so a by-name runtime lookup buys nothing. §0.9's stamp-only refusal and the sheet's summary item 3 are superseded; step 6 makes no kit edit.
2. **The sender owns its own `EntityMovementServerStateFlagsPass`** (held by its engine, MeshStateFanout, so the consume rules are unit-tested there). It Begins at build start, Records the INNER kit handler after that handler's one successful, append-only-checked write, ConsumeAlls after the fan-out of a completed build, and skips ConsumeAll when a reliable send of that build failed (the next Begin drops the records: at-least-once). `MESH_SENDER=measure` never Begins, Records or Consumes. The wrapper never implements `IEntityMovementServerStateFlags`. Reason: the kit's pass is protected and its Begin would drop ours (BGNM:110-111, :705); the write no longer clears (BIEMF3D:1373-1375), so without our consume every one-shot goes reliable forever.
3. **Hooks come from `MeshMapNetworkManager.OnServerUpdate` (Load:58-71).** Pre-kit work (deferred flush, wrap queue, rewraps) before `base.OnServerUpdate`; the build after the kit's `finally`, only when base returned; both timed into one `MeshWorkProbe.Meter.AddTickWork` call (MeshWorkProbe.cs:289) after the build. No OnTick subscription (RegisterMessages runs once, LNM:95-98/:150-157, so it is lost after a restart). The component is added in `MeshMapNetworkManager.Awake` (MMNM:96-101) after `InstallSendMeter()` (:99) and before `base.Awake()` (:100), so BGNM:125 collects it. The only other per-frame work is the deferred flush in `MeshStateSender.Update` (decision 27).
4. **Never skip a new pair.** Reason: the shipped Jobified AOI creates pairs between ticks (JAOI:248-340) and spawns flush at the next tick's sync (LNGM:111) before the send; the kit delivers the first record (send.md finding 4). The sheet's creation-build skip is removed; "due on the next 3 builds" stays as the first-send boost.
5. **Never withhold an owner pair.** Withhold on an owner pair is treated as Hz 0 (still gets urgent and reliable records) and logged once per sender start; Withhold on a non-owner pair drops everything, one-shots included, for good, and the build still consumes. The Withhold doc comment in `Mesh/Sync/MeshSyncContracts.cs:99` changes (documentation only, no API change; `MeshSyncContractTests` pins no comment text). A one-line note to the space team goes with the step 6 hand-off (user decision 2026-10-02). Reason: a withheld owner never confirms a teleport and WaitClientTeleportConfirm has no timeout (BIEMF3D:1754-1760).
6. **Urgent and reliable.** Urgent = the write set sendReliably (every kit one-shot does) or DiscreteVersion changed. A sendReliably record goes ReliableOrdered to every current subscriber that build, whatever its tier or phase; a DiscreteVersion change makes the source due to every subscriber on this build and the next 2. Reliable records are never deferred; `FlushDeferred(N)` runs before `Build(N+1)`. A reliable record too big for the capped writer goes alone in its own uncapped ReliableOrdered packet (kit parity, BGNM:739-745); only unreliable too-big records are skipped and counted.
7. **Write every source that has at least one subscriber on every build**, not only when some pair is due; receivers come from `identity.GetSubscribers()` at build time (LNI:726), never from a cached list. Reason: urgency is learnt only from the write (no HasServerStateFlags member, source.md 1.2).
8. **The kinematic body gets a sender-owned state.** While registered with the sender (`SentBySender = true`) its kit-facing `WriteServerState` returns false and writes nothing, and `WriteState` writes (one writer, one sampleTimestamp per build). It keeps its stamp shape and does not implement the CE-12 interface. Whoever takes the body out of the fan-out clears the flag (Puppets before End, End itself, the drop callback of decision 23), so a body is never left with no writer.
9. **The adapter uses `MeshMovementHandlerSlots.For(manager)`** (the instance Puppets uses, Puppets:68), through the pure `MeshKitWrapQueue` (decision 21). `OnReplaced` unregisters the wrapper synchronously; the `LayerRemoved` handler only queues a rewrap; the sender stays inactive on the grid path (BGNM:135).
10. **Verification counts EntityState RECORDS, not packets.** `MeshSendMeter` reads the int32 record count of every msg-119 packet and keeps exact record totals per delivery; the Send window line gains a `records` group whenever the window counted one (decision 25). `MESH_SENDER=measure` builds after the kit and changes no bytes.
11. **`ServerMeshCe12Check`** (TestMap, `MESH_CE12_CHECK=1`) classifies `stamp | perCall | pass | absent | stuck` on a hidden, server-owned rig character; today's kit reports `pass`.
12. **The step 6 keys move into `p0tools.ENV_REGISTRY` and `regress.ENV_KEYS` now** (10 keys, see Y), with the counts updated.
13. **(added) `MESH_SENDER_RESIDUAL_PROBE` is dropped** (user decision 2026-10-02). The kit loop's residual (iterating wrappers that return false) is already the Work ticks `move` part under `MESH_AOI_TIMING=1` (send.md 2.2), and the Work ticks `send` sample is then exactly "tick send work" (residual plus the sender's AddTickWork). DROPPED_KEYS reason: "dropped in step 6 (decision 13): the Work ticks move part already times the kit's movement loop under MESH_AOI_TIMING=1".
14. **(added) Puppet error is measured as `viewErr` on phantom observers.** For a rotating 10 % sample of bound virtual phantoms, the phantom transport decodes each swallowed 119 packet and keeps the newest record position per object, with the frame it arrived; once per frame the window samples the X/Z distance between that position and the object's server position now, for entries refreshed within the last 100 ms only (an object that left view or was destroyed is never compared). Both arms measure it identically. Bots have no truth source on the client, so the 2-bot variant gates records/s and bot health only, and the phantom rows carry the position-error gate (user decision 2026-10-02).
15. **(added) Allow-list by exact type, held by the wrap queue instance.** `MeshKitMovementStateSource.IsDefaultAllowed(Type)` is exact `BuiltInEntityMovementFunctions3D` or `NavMeshEntityMovement`; `MeshKitWrapQueue.AllowHandlerType(Type)` adds more and `MeshStateSender.AllowHandlerType` forwards to it (kept for calls made before the queue exists). No static set (statics leak across plays, the step 5 eye lesson).
16. **(added) `MeshMovementHandlerSlots.Holds(uint id, IEntityMovementDataHandler layer)`**, a read-only member: true while that exact layer sits in the slot and this instance installed it. The per-build "is my wrapper still there" check uses it (kit re-registration evicts wrappers behind the slots, BIEMF3D:222-226, NMEM:139-143).
17. **(added) Measure mode measures adapter sources only.** Wrappers are built but never installed, so `Holds` is always false for them: measure mode's per-build check is instead "the slot's kit handler is still this wrapper's Inner" (`TryGetKitHandler`). An id already registered is skipped at drain. Bodies are never registered (a post-kit body write could end its stamp before a catch-up tick's kit write); with kinematic puppets a body's object is refused (`HasLayer`) and counted by the kit only. Measure-mode reliable counts are an underestimate (the kit already consumed the flags) and are labelled so. The post-kit write assigns BIEMF3D's server-local `MovementState` one frame earlier than the next kit write would (no wire bytes; send.md §1.4): accepted, and SETUP §7 says so (user decision 2026-10-02).
18. **(added) Stale kit flags behind a body stay kit parity.** Flags pending in the kit handler when a body replaces the wrapper go out once on the rewrap build after End and are consumed then (q4 H13 hardening not taken).
19. **(added) Pre-kit work runs only on the first kit tick of a frame** (when a build will follow), so a wrap made between two catch-up ticks never hides an entity from both the kit and the sender for a tick.
20. **(added) The Sender and CE-12 parsers land now** in a new `Tools/ServerMeshing/p0sender.py` (p0tools is past the ~500-line rule at 508 lines, and the sender lines are a step of their own beside p0phantom's step 5 lines), not at step 8.

The queue holds identities (the sender resolves ids through the public `Assets.TryGetSpawnedObject`), so it needs no LiteNetLibManager internals.
22. **(critic) The sender configures itself on the first BeforeKitTick after a start**, not in its OnStartServer. Components' OnStartServer runs at BGNM:254-257, before `MMNM.OnStartServer` reaches `ApplyBandOverride` (MMNM:654-699, call at :698; Load:86-102), so a default R0 read there would miss `MESH_BAND`. The grid check, slots and event subscriptions stay in OnStartServer.
23. **(critic) The fan-out reports every source it drops** (append-only violation, null or destroyed identity) through a callback, so the wrap queue restores a dropped wrapper's kit handler and refuses its id, and a dropped body gets `SentBySender = false` (the kit sends it again).
24. **(critic) The 20-reliable-builds warning (`stuckReliable`) watches adapter sources only.** Their consume is ours; a direct source (the body, step 7's stand-ins "reliable while a teleport is unacknowledged") may legitimately stay reliable.
25. **(critic) New line groups never change an old line.** The Send window's `records` group is printed only when the window counted a 119 record or an unreadable 119; the Phantom window's `viewErr` group only when `ShowViewErr` is set (the `ShowFighting` precedent). So step 5's exact-line tests (`MeshSendMeterTests.cs:15-16`, `:229`; `ServerMeshPhantomWindowTests.cs:9-10`) stay valid unchanged, and p0phantom treats both groups as optional.
26. **(critic) The Sender window carries pairs by classified Hz** (gauges at the last build) and the withheld non-owner pairs, so step 8 can check G1's "≥ 10 Hz within 1 km / 40 m" and "≥ 1 Hz (5 Hz) for every subscribed pair" from logged lines.
27. **(critic) A deferred half is flushed on the frame after its build**, from `MeshStateSender.Update` (when the frame differs from the build's), and otherwise by the next BeforeKitTick or Build step 2. Flushing only at the next tick would send the second half together with the next build's first half, which defeats spreading.

## P. Pure Mesh/ types (Mesh/Sync, new files unless noted)

**`MeshStatePacketWriter.cs`** — `public sealed class MeshStatePacketWriter`
- `public const ushort EntityStateMessageType = 119;` (equals `GameNetworkingConsts.EntityState`; a test pins it). `public const int MaxPacketBytes = 1020;` (SS:12).
- `public MeshStatePacketWriter(int maxPacketBytes = MaxPacketBytes)`: throws ArgumentOutOfRangeException naming `maxPacketBytes` below 64 or above 1020. Owns one `NetDataWriter` (autoResize, capacity maxPacketBytes + 4).
- `public void Begin(long timestamp)`: `Reset`, `PutPackedUShort(119)`, `PutPackedLong(timestamp)`, `Put(0)` placeholder; remembers the count offset; Count = 0; `Timestamp` = timestamp.
- `public bool TryAppend(uint objectId, byte[] buffer, int offset, int length)`: throws on null buffer or a span outside it; false (nothing written) when `Writer.Length + RecordSize(objectId, length) > maxPacketBytes`; else writes `PutPackedUInt(id)`, `Put(int length)`, `Put(buffer, offset, length)` (raw bytes, never `PutBytesWithLength`) and Count++.
- `public int Count`, `public bool IsEmpty => Count == 0`, `public int Length`, `public int HeaderLength`, `public long Timestamp`.
- `public NetDataWriter Finish()`: patches Count little-endian at the remembered offset (SetPosition, Put, SetPosition back, so `Length` is the packet's end) and returns the writer (valid until the next Begin).
- `public static int PackedUIntSize(uint value)` (1..5, the `PutPackedULong` boundaries 240/2287/67823/16777215); `public static int RecordSize(uint objectId, int length) => PackedUIntSize(objectId) + 4 + length;`
- `public int MaxPayload(uint objectId)` = maxPacketBytes − HeaderLength − 4 − PackedUIntSize(id) (1004 − idBytes at 1020 with the usual 12-byte header).
- `public static void WriteSingle(NetDataWriter writer, long timestamp, uint objectId, byte[] buffer, int offset, int length)`: an uncapped one-record packet (count 1) for the oversize reliable path.
- Layout exactly the kit's (BGNM:715-726, :741-743, :767-769): `[packed ushort 119][packed long ts][int32 count]{[packed uint id][int32 len][len bytes]}`. Packet boundaries differ from the kit's (it splits at `pos + len + 8 >= 1020`, BGNM:750-751, and can send a count-0 packet); records do not.

- **Storage (warm-up only):** sources in a swap-remove array with a `Dictionary<uint,int>` index and a per-slot generation (bumped whenever a slot is vacated or refilled); per source a pair table (`Dictionary<long,int>` into parallel arrays: connection, connection slot + generation, rate, divisor, send phase, classify phase, boost builds left, last-seen build, owner flag, marked flag) so a pair visit costs one dictionary probe; per source its position for this build (read once); connections in a slot table (`Dictionary<long,int>`) each holding an unreliable and a reliable `MeshStatePacketWriter`, its anchor for this build (looked up once per connection per build, NaN distance when none) and a generation; one payload arena (growable `byte[]` with per-source offset/length for Full and Compact); one scratch `NetDataWriter`; a deferred entry array `{connection slot, connection generation, source slot, source generation, object id, variant}` plus the deferred build's timestamp.
- **Build(ts, frameIndex, host)**, in order:
  1. `frameIndex == lastFrame` → Skipped++, return (at most one build per frame; catch-up ticks are skipped and write nothing).
  2. `FlushDeferred` if anything is deferred; buildIndex++; arena reset; every connection's writers are begun with ts (nothing of an earlier abandoned build survives); unless measure, `_flags.Begin()`; reliableFailed = false.
  3. For each source: identity null or destroyed → drop it (logged once by id; `dropped(source, "its identity is gone")`). No subscriber other than `host` → no write. Else scratch.Reset, put a 4-byte guard (the object id), call `WriteState(ts, scratch, out reliable)` inside try/catch (an error logs `State sender error: object N (Type) write failed: <cleaned message>` once per source per window, counts WriteErrors, no record, sent again next build). Length below 4 or a changed guard → AppendOnlyDrops, the source is dropped (logged naming the id; `dropped(source, "it broke append-only")`). false → NotWritten (nothing, not recorded); true with 0 payload bytes → EmptyWrites (nothing, not recorded). Otherwise copy the payload into the arena; unless measure, `_flags.Record(FlagsHandlerOf(source))`; Writes++. Drops during the walk never disturb the iteration (walk backwards or compact after).
  4. Adapter sources only (decision 24): consecutive reliable writes per source; at exactly 20 log once per source per start `State sender: object N (InnerType) wrote 20 reliable builds in a row; its one-shot flags are not being consumed`, StuckReliable++.
  5. DiscreteVersion changed since its last write → urgent builds = 3 and every pair re-classifies.
  6. Walk `identity.GetSubscribers()`; skip `host`; find or add the pair (new → boost 3, classify now; never skipped). IsOwner = `identity.ConnectionId == connection`, read live; a flip re-classifies. Classify when new, marked, after a version change, or when `(buildIndex + classifyPhase) % classifyEveryBuilds == 0`, where classifyPhase = stable hash(objectId, connection) % classifyEveryBuilds (re-classification spreads evenly over the builds; reusing the send phase, which is 0 at divisor 1, would put every 20 Hz pair on the same build). Distance from the connection's cached anchor and the source's cached position (NaN when no anchor; 3D or X/Z per settings). `policy.Classify(source, in context)`: Withhold on an owner → Hz 0, Full, WithheldOwner++ and one warning per start; Withhold on a non-owner → nothing this build. A Hz outside {0,1,2,5,10,20} from a custom policy is logged once per policy type and treated as the next lower allowed value (HzClamped++). Hz 0 has no routine records; else divisor = max(1, round(buildHz / Hz)) and send phase = stable hash(objectId, connection) % divisor (an integer mix, no allocation).
  7. Route: reliable → the connection's reliable writer (Full only); a record above its MaxPayload → `WriteSingle` into the scratch oversize writer and sent at once ReliableOrdered (OversizeReliable++). Not reliable and (urgent builds > 0 or boost > 0 or (Hz > 0 and (buildIndex + sendPhase) % divisor == 0)) → unreliable, Full when urgent or boosted, else the pair's variant (Compact written lazily into the arena at most once per build, only for an `IMeshCompactStateSource`). A record above MaxPayload on the unreliable path → TooBigSkipped++ and one log per source per window. With spread on, routine (not urgent, not boosted) unreliable records of every second source in registry order go to the deferred list instead.
  8. A full writer is finished and sent at once (UnreliablePackets/ReliablePackets++), then begun again with the same ts. Pairs of a walked source not seen this build are removed (a source not walked this build keeps its pairs).
  9. Finish and send every non-empty writer; per connection the final reliable packet goes before the final unreliable one (as the kit's final sends do; the order carries no meaning, since the kit sends unreliable splits mid-loop). - A1 (H): measure mode's per-build check used `Holds`, which is always false for an uninstalled wrapper, so every measure wrapper was unregistered and re-queued each build; measure now checks "kit handler is still Inner" and skips registered ids (decision 17, MeshKitWrapQueue).
